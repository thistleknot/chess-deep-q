***definitions***

- :Expert-iteration-cycle: is one turn of the improvement loop: a strong search plays games and emits (position, a policy target, and the value target); the net's heads are trained toward those targets; search over the improved net then produces better targets. Search is the policy-improvement operator; no policy gradient is involved. The value target is always the :Lambda-return: (value-target); the policy target and the cost depend on the :Search-profile:.
- :Search-profile: is which search generates self-play — THE improvement operator. Expert iteration amplifies ONLY when this operator is STRONGER than the raw net; the measured history (see :Self-play-bootstrap:) is one long lesson in operator strength — every plateau used a weak one.
  - **PUCT (PRIMARY — the operator with amplification):** hundreds of SELECTIVE playouts/move over the net's policy prior + value, producing a :Visit-distribution-target:. It is a genuinely stronger operator than the raw policy — the property net-minimax@d1 and the sampled/optimistic beam both LACKED. Its per-move cost is dodged by BATCHING: the conv/resnet net is launch-bound at ONE position (~9.6 ms) but fast BATCHED, and PUCT run across many CONCURRENT self-play games collects a large leaf batch per net forward, so the net's throughput is usable exactly here — where per-node alpha-beta and sequential d1 could not batch. Value target = the committed outcome (:Lambda-return:); policy target = the root visit distribution.
  - **Net-minimax (SECONDARY — measured FLAT @d1):** the value net inside shallow `net_search`. Cheap, but @d1 it is NOT stronger than the raw net → no amplification (measured: flat ladder). Valid only at a depth where it out-evaluates the policy; on this hardware batched-PUCT reaches the amplification regime that per-node minimax cannot.
- :Off-policy-handoff: is the annealed shift of the self-play behaviour/data source from a strong :Teacher: to the net's own :Search-profile: play, driven by :Demo-share:. It is sequenced by DATA QUALITY, not compute: the teacher is the stronger player (better data) until the net approaches it, after which self-play generates data that can EXCEED any fixed teacher — the mechanism for surpassing the teacher toward frontier. The teacher need NOT be Stockfish: the repo's own ~1672 alpha-beta engine (`engine.py` pst, CPU, free) is a valid :Demo-share:=1 behaviour source — learning the value+policy net OFF-POLICY from its trajectory OUTCOMES (value = z / :Lambda-return:; policy = its cloned move) starts the net near the engine's level. This is the fix for the d1 self-play failure: that loop bootstrapped from a WEAK net (no amplification); an engine-teacher bootstrap starts near the frontier, where subsequent self-play search DOES out-amplify the net. Implemented in `offpolicy_bootstrap.py`; SF stays the :Ladder: gate.
- :Visit-distribution-target: is the normalized root visit count vector at move temperature τ, stored as the policy target for the position; it is a valid target only when the game's simulation budget made visits informative.
- :Training-game-budget: is the per-move simulation budget used in self-play *training* games: it must guarantee visits-per-candidate at or above the informative threshold, reconciling visit targets with the :Root-selection-rule: (which exists precisely because low-budget visits are uninformative). Fast low-budget profiles are for measurement and human games, not for generating policy targets.
- :Root-dirichlet-noise: is constant Dir(α) noise mixed into the root prior in self-play training games only — the explicit, bounded carve-out from "never anneal toward randomness": it is fixed structured exploration, never annealed, and always OFF in :Measurement-game:s.
- :Surpass-teacher-gate: is the :Elo-gate: at the :Teacher:'s own anchor-measured strength; only after it clears may :Demo-share: reach zero.
- :Amplification-experiment: is the definitive, falsifiable RL test on this hardware: run batched-PUCT expert iteration and track the :Ladder: curve PER ITERATION. RISING across iterations ⇒ the operator out-amplifies the net, RL is viable here (then it is a compute-scaling question); FLAT (like d1) ⇒ the shallow-net-RL path is WALLED on this hardware and stops WITH PROOF, not conjecture. It is the fair test none of the four plateaued attempts gave self-play — the FIRST that pairs a strong operator (PUCT) WITH a usable net throughput (parallel-game batching). The milestone is beating the heuristic-1ply rung, the wall every prior attempt hit. FIRST MEASURED RESULT (`puct_selfplay.py` hybrid, 12 iters, eps 1→0): the d1-probe curve was FLAT (vs_heuristic bounced 0–0.25) — BUT that probe is BLIND to this agent. Re-measured with the net's ACTUAL search (`puct_eval.py`, net+PUCT@80), the agent went from the d1 probe's 0/16 LOSSES to **16/16 DRAWS vs heuristic-1ply (parity)** — the FIRST RL config in the repo that does not lose to the heuristic. Parity, not yet surpassing (still ~0.72 vs random → net weak, search defends). The path (AlphaStar hybrid + search) is validated; surpassing is the remaining, compute-bound question.
- :Search-measured-gate: is the CORRECTED per-iteration measurement: the :Ladder: MUST place the net's ACTUAL agent — net+PUCT (`puct_move`, argmax over root visits, no Dirichlet) — on the rungs, NOT the d1 net-minimax probe. Rationale is measured, not stylistic: the d1 probe reported 0/16 losses for an agent that draws 16/16 with its real search — it does not measure the thing being trained, so a flat d1 curve is not evidence of a flat agent. The search-measured ladder is kept cheap (reduced playouts, ~10 games/rung) but uses the same operator the agent plays with. PUCT_PLAYOUTS is the operator-STRENGTH dial: raising it strengthens the improvement operator (better visit-distribution targets + value backups = more amplification headroom), at linear per-move cost.
- :Self-play-bootstrap: is the leaf evaluator the self-play search STARTS from, along the :Prior-lineage:. Two valid entry points: (a) the HAND HEURISTIC via an eps-blend leaf — board_eval = eps·tanh(pst/…) + (1−eps)·:Learned-value:, eps annealing 1→0 so the heuristic guides early self-play and the net takes over (pure prior-lineage, NO teacher in the loop); (b) a DISTILLED net snapshot (eps=0 from a checkpoint, e.g. the Stockfish-distilled tower — warmer start). SF is never in the self-play loop under either; it is only the :Ladder: gate. The two bootstraps are compared as a :Ladder:-measured experiment — each one's per-iteration ladder curve — to see whether unaided heuristic self-play catches the distilled start (and whether either catches SF). FIRST MEASURED RESULT (`benchmark.py`, 8 iters, net-minimax d1, n=12): NEITHER bootstrap climbed toward the search reference — A (alpha-beta pst @0.3s) = 1.00 vs heuristic-1ply while B1/B2 stayed flat at 0.0–0.5; value loss fell (net fits its own outcomes) but external strength did not rise. Diagnosis: the d1 improvement operator is too shallow to AMPLIFY (expert iteration climbs only when the search is stronger than the raw policy), and self-play from a weak net feeds itself weak-outcome data. Implication: on this hardware the net's value is better spent as a hole-free leaf eval INSIDE deeper search (:Search-profile: at higher depth / the NNUE synthesis) than as a standalone self-play player; useful self-play needs deeper per-move search, which is throughput-bound. CORRECTION (the repo's intent is chess-through-RL, so the earlier "better spent inside search" was strength-true but goal-incomplete): the d1 result CONDEMNS d1, NOT self-play — the loop machinery works (value loss fell), there is simply no amplification at 1-ply. The fix is not to abandon self-play for supervised strength but to make deeper self-play AFFORDABLE: the µs-cheap :NNUE-eval: moves the same per-move budget to d3+, the amplification regime, after which the eval retrains on self-play :Lambda-return:s (TD-Leaf). RETEST at depth before concluding; the flat d1 curve is not a verdict on self-play — it is the :NNUE-kill-check: Stage-2 experiment waiting on the fast eval. FOUR-WAY-PLATEAU UPDATE (measured, this iteration): three further RL configs landed at the SAME plateau — beats random, loses ~0/N to heuristic-1ply — (i) off-policy bootstrap from the 1672 engine (value = z, policy = cloned move; `offpolicy_bootstrap.py`, vs_heuristic ~0), (ii) the standalone A2C + 8-ply sampled beam (`mcts_chess.py`, 400 episodes, 0/20 vs heuristic WITH its search on). NNUE v1 is FALSIFIED (Stage-1 failed: 281 µs/call = 8× pst → lost equal-time; d2 808 / d3 −280 vs pst 1367/1672 → lost equal-depth). The unifying diagnosis is now FIRM: every attempt used a WEAK improvement operator (d1 net-minimax; the sampled/optimistic beam), and the NNUE "µs per-node eval" fix MIS-READ the wall — the net is slow at a SINGLE position but fast BATCHED, so the fix is not a faster leaf eval but BATCHING the net across parallel PUCT games. The path forward is therefore the batched-PUCT :Search-profile: (now PRIMARY), and the verdict is the :Amplification-experiment:, NOT another leaf-eval iteration.
- :Strength-matched-opponent: is an OPTIONAL self-play opponent mode for early training: rather than a second network, one side is the same net with its selection temperature modulated to play "just above" the reference player's strength, at a setpoint of mean + k·σ of that player's per-move quality (regret) distribution. It reuses the regret tracking in `difficulty.py` (restoring the σ term the human-difficulty path dropped) and the temperature↔strength map in `elo_calibration.py`. It is a zone-of-proximal-development / matched-difficulty curriculum, NOT gating, league, or a separately-trained second net.

- :Spearhead-profile: is a THIRD :Search-profile: (alongside PUCT and net-minimax): the SOUND alpha-beta :Deployed-agent: (search-mcts) as the self-play improvement operator — :Full-width-floor: (full width to d3, the shaft) + :Phi-widening: (the narrowing refutation-preserving "spearhead" tip) + move ordering + :Tree-reuse:, with the critic as :Critic-leaf:. Unlike the FALSIFIED operators (d1 net-minimax = too shallow to amplify; the sampled beam = optimism-biased, dropped opponent refutations), the spearhead is a GENUINELY STRONGER operator than the raw critic (looks ahead soundly, keeps every tactical refutation), so it CAN amplify. The A2C plateau (`mcts_chess.py`, 0/20) was bolted to the SAMPLED BEAM, not this — so advantage actor-critic is UNTESTED with a sound operator. Its per-move cost is the SEARCH (not a batched net forward), so it parallelizes by :Parallel-selfplay: (many CPU workers), not net-batching.
- :Advantage-actor-critic: (:DA2C:) is the POLICY-GRADIENT training mode of the :Expert-iteration-cycle: — the alternative to the cross-entropy-to-:Visit-distribution-target: AlphaZero mode, requested explicitly. It is DISTRIBUTED advantage actor-critic (the DA2C skeleton, Zai & Brown ch5): a SHARED-MEMORY dual-head critic (value + policy), N PARALLEL worker processes each running :Spearhead-profile: self-play and doing ASYNC gradient updates on the shared model (`torch.multiprocessing` + `share_memory()`; the small CPU critic is WHY this is clean — the launch-bound GPU resnet could not share-memory). Per move the spearhead emits a BACKED-UP value V_search(s); the gradient step is CRITIC loss = (V_net(s) − V_search(s))² (regress the value toward its own deeper SOUND search = the self-improve bootstrap) + ACTOR loss = −logπ(a|s)·advantage, advantage = V_search(s·a) − V_net(s) (reinforce moves the spearhead found better than the critic expected). Mechanics from the chapter: CLC down-weights the critic loss (actor learns faster), the value is DETACHED in the actor term, and the policy head DETACHES the shared trunk so the actor owns it. Targets are SOUND (spearhead-backed), so this is NOT the falsified A2C — it is the untested sound-search × policy-gradient combination. Value target is the :Lambda-return: (N-step bootstrapped, reducing to outcome z at the episode floor).

***functional specs***

- The :Self-play-bootstrap: must be a prior-lineage leaf, annealed toward the net, with SF out of the loop.
  - Given the heuristic bootstrap, Then early self-play leaves are the hand heuristic (eps→1), eps anneals to 0, and the net trains on the resulting outcomes with no Stockfish in the loop.
  - Given the distilled bootstrap, Then self-play starts from a distilled net snapshot (eps=0).
  - Both bootstraps are placed on the :Ladder: per iteration for comparison; SF is the gate, never the in-loop teacher.
- Self-play must emit expert-iteration targets; the value target is profile-independent, the policy target is profile-specific.
  - Given a self-play move under the net-minimax :Search-profile:, Then the stored policy target is the deeper search's chosen move (cloning) and the stored value target is the :Lambda-return: in the :White-absolute-frame:.
  - Given a self-play move under the PUCT :Search-profile:, Then the stored policy target is the root :Visit-distribution-target: and the value target is the same :Lambda-return: (which reduces to outcome z as :Bootstrap-share: β → its floor).
- The :Off-policy-handoff: must be data-quality-sequenced, not compute-gated.
  - Given the net measures weaker than the :Teacher:, Then :Demo-share: keeps the off-policy source predominantly SF (better data); Given the net approaches the :Teacher:, Then the source anneals toward the net's own :Search-profile: self-play, which may exceed the teacher.
  - Self-play is NOT withheld because it is expensive — the net-minimax profile is cheap; it is sequenced after distillation only because SF is the stronger data source until the net catches up.
- Replay batches must honor the annealed :Demo-share:.
  - Given :Demo-share: d at current :Gated-progress:, Then each training batch draws fraction d from the :Cumulative-dataset: and 1−d from self-play replay.
- Exploration noise must stay inside training games.
  - Given a :Measurement-game:, Then :Root-dirichlet-noise: and move temperature are disabled and the agent plays argmax.
  - Given a self-play training game, Then :Root-dirichlet-noise: is applied at the root with constant α — it is never a schedule knob.
- Policy targets must be budget-qualified.
  - Given a training game whose simulation budget satisfied visits-per-candidate >= VISITS_PER_CANDIDATE_MIN, Then its policy targets are stored.
  - If the budget fell short, Then the game's policy targets are discarded while its value targets may be kept.
- The teacher is outgrown by measurement, not by schedule.
  - Given the :Surpass-teacher-gate: clears (measured Elo > the teacher's anchor-measured Elo), Then Stage 3 may continue teacher-free (:Demo-share: floor 0) and the teacher remains only as a measurement reference.
  - Given the gate has not cleared, Then :Demo-share: >= DEMO_SHARE_FLOOR (guards catastrophic forgetting of teacher knowledge).

- The :Strength-matched-opponent: is optional, early-only, and annealed out — the standard mode is full-strength symmetric self-play. (This encodes the critique: a deliberately temperature-weakened opponent produces easier, lower-quality games and noisier visit-count/value targets; keeping it late would cap target quality. Its value is faster early improvement against an opponent slightly above the learner, not final strength.)
  - Given the :Strength-matched-opponent: is enabled, When it selects a move, Then its temperature is modulated so its expected per-move quality tracks the setpoint mean + k·σ of the reference player's regret distribution (opponent slightly stronger than the learner).
  - Given rising :Gated-progress:, Then the σ-offset k and the matched-opponent's temperature anneal toward zero, converging to full-strength symmetric self-play (both sides argmax + :Root-dirichlet-noise:) before the targets are used to chase the :Surpass-teacher-gate:.
  - Given the :Strength-matched-opponent: is disabled (the default), Then both sides play the same full-strength net with :Root-dirichlet-noise:.

- The :Amplification-experiment: must run the batched-PUCT profile and report a PER-ITERATION :Ladder: curve — it is the primary RL deliverable, not a side metric.
  - Given batched-PUCT expert iteration, When each iteration completes, Then the net is placed on the :Ladder: (vs random / heuristic-1ply / SF@1320) and the score is recorded; a RISING curve across iterations confirms amplification, a FLAT curve falsifies the shallow-net-RL path on this hardware.
  - Given the PUCT :Search-profile:, Then the per-move net cost MUST be amortised by batching PUCT_PARALLEL_GAMES concurrent games into one net forward per playout step (the launch-bound single-position cost is otherwise prohibitive).
  - Given a completed PUCT move, Then the stored policy target is the root :Visit-distribution-target: over legal moves (summing to 1) and the value target is the outcome in the :White-absolute-frame:.
