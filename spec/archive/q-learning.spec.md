***status legend*** — this spec is tiered like a skill: **definitions / implementation reqs / functional specs = COMMITTED** (built and validated); **future direction = documented, NOT built** (sound but deferred for simplicity); **open questions = undecided, to be resolved by MEASUREMENT (Elo), not argument.**

***definitions***

- :Afterstate-value: is V(s) over the raw board state (the 769-dim piece-square one-hot from Merge 1's `encode`), computed as a torch module (`arch="linear"` = a learnable piece-square table by default; `arch="mlp"` behind a flag). The policy scores each legal move's RESULTING board and takes the max — Q-learning's off-policy `max_a` expressed over afterstates, which sidesteps chess's ~4672-action masking problem. White maximizes, Black minimizes the white-absolute V.
- :TD-lambda-target: is the forward-view λ-return `G^λ_t` used as the regression target for every visited position (reuses `value_targets.lambda_return`): `G_t = r_t` at a terminal, else `G_t = r_t + γ·[(1−λ)·V(s_{t+1}) + λ·G_{t+1}]`, White-absolute. **λ = 0 ⇒ one-step Q-learning** (`r + γ·V(s')`); **λ → 1 ⇒ Monte-Carlo**. This is the single framework that carries both the user's α (SGD step size) and λ (TD↔MC dial) knobs. `γ < 1` discounts, so a shorter mate is worth more than a longer one — which alone pushes against Merge 1's draw-collapse.
- :Replay-buffer: is a bounded `deque(maxlen)` of `(encode(s_t), G^λ_t)` pairs, sampled UNIFORMLY for minibatch SGD. Every game contributes — wins, losses, AND draws (the "train on all games" fix; Merge 1 discarded draws and starved itself). No prioritization, no sample weighting (simple convergence basics; per S&B §8.4 prioritization is a speed optimization, not required for convergence). CAVEAT (honest limit of the off-policy justification): the buffer stores FINISHED λ-return targets FROZEN at generation time — not raw transitions re-bootstrapped at training time (DQN-style) — so with λ>0 an old entry embeds the OLD net's bootstraps and actual continuations played at the OLD (higher) τ: old entries ARE biased toward the policy that generated them. "Old experience stays valid because Q-learning is off-policy" (S&B §6.5) holds fully only for re-bootstrapped transitions or λ=0. The admixture horizon is CONTROLLED by `QLEARN_BUFFER_EPOCHS` (console "buffer (epochs)"): >0 caps the window at ~that many epochs of positions (epoch_games × ~64 plies); 0 = legacy absolute 100k cap (≈8 epochs at 200 games/epoch, ≈0.8 at 2000). Smaller horizon = fresher/less-admixed targets, less variance smoothing; buffer is created EMPTY each run, so there is never cross-run/trial admixture.
- :Temperature-schedule: is exploration by SOFTMAX over afterstate values, NOT ε-greedy. The behavior policy picks move a with probability ∝ exp(σ·V(afterstate)/τ), where σ = +1 if White to move else −1 (each side softmaxes toward ITS good outcomes). τ anneals on a single warmup-ratio schedule from high (`:Optimistic-start:` — near-uniform) toward a low floor, NEVER to 0. Chosen over uniform ε-greedy because it explores value-GRADED — plausible near-best moves often, obvious blunders almost never — which matters in chess's large, blunder-heavy action space (the AlphaZero "temperature not uniform" recipe). **Implicit-annealing property:** because :Afterstate-value: is tanh-bounded and starts ≈0 everywhere, softmax is near-uniform early (auto-explore) regardless of τ, and sharpens on its own as the value develops spread — so τ MUST be calibrated to the value's actual magnitude (tanh gaps are small; ~0.05–0.2), and the explicit schedule only fine-tunes that automatic sharpening. It is a GENERIC, stateless schedule parameterized by a SINGLE knob — the **warmup ratio** `WARMUP`, now the e-folding fraction of a shared ASYMPTOTIC form `anneal(start, end, progress, w) = end + (start−end)·e^(−progress/w)`: τ decays fast-then-slow toward τ_floor (~63% done at progress=WARMUP, ~92% at 2.5×WARMUP) and NEVER reaches it — the exploration room never fully closes. The same `anneal` shape drives :Lambda-anneal: (one intent, one shape). NOT gated on mid-training strength (no Elo measurement inside the loop). Strength enters ONLY as the outer Optuna objective (see :Elo-objective:). Optuna tunes **{γ (decay), α, λ, WARMUP}** over grounded ranges (TPE seeded at prior means — see `tune_qlearn.py`); SAMPLE SIZE and BATCH SIZE are PASSED to the study (CLI args, same as the console form), not searched; τ_start=0.7 and τ_floor=0.05 stay fixed env-overridable defaults. Trials run the SAME regime as the console (frozen generator, asymptotic anneals). CRITICAL: this is the BEHAVIOR policy only — the :TD-lambda-target: stays GREEDY/max (off-policy). Using the softmax value as the target instead would silently become Expected-SARSA / soft-Q, a DIFFERENT rung, and MUST NOT be conflated here.
- :Proxy-strength: is the cheap per-iteration strength signal: greedy-policy (τ→0) win-rate vs the 1-ply PST mover (`measure_ladder.heuristic_mover`, instant) and vs the uniform-random mover. Plotted live every iteration.
- :Elo-patience: — the epoch early-stop signal is the SAME axis as the Optuna objective: the epoch's POOLED nominal score vs SF@1320 (all the epoch's live-Elo games — steadier than any single sample), scaled to dominate: `strength = 100·(Σ sf_pts / Σ sf_n) + proxy`. The :Proxy-strength: term only breaks ties while every epoch is still a shutout, and is the sole signal when `EPOCH_ELO_GAMES=0`. Patience compares against the BEST epoch so far (a rebound below the best still counts stale); a lucky-probe peak killing a run is mitigated by pooling, not eliminated — prefer bigger epochs (2000) or higher patience for long runs.
- :Calibrated-elo: is the real yardstick, run periodically (not every iteration — it is slow): the greedy policy's score vs Stockfish limited to `UCI_Elo = 1320`, converted `1320 + elo_diff(score, n)` where `elo_diff(s, n) = 400·log10(s/(1−s))` with s clamped to `[1/(2n), 1−1/(2n)]` — the HALF-POINT bound, so a 0/n shutout maps to a finite "at or below" rating on the actual scale (~775 @ n=12, ~562 @ n=40), never a −280 clamp artifact. The NOMINAL score (W + D/2 out of n, `sf_pts`/`sf_n`) is logged and plotted alongside; the Elo is derived from it. The :ETA: to Elo 1600 is a trend fit on this series.
- :Lambda-anneal: — the base λ is SCHEDULED by the same asymptotic `anneal` as τ: `λ_base(p) = anneal(λ_start, λ, p, LAMBDA_WARMUP)`, λ_start=0.95 (`QLEARN_LAMBDA_START`; set ≤ λ to disable), `QLEARN_LAMBDA_WARMUP` defaulting to `WARMUP` (lock-step dials). λ decays fast-then-slow toward the tuned base and never reaches it. **Direction disposition** (two literature forces, both strongest early): H1 value-trust says λ decays with τ — an untrained V makes bootstrap targets information-free (tanh init ≈0), so MC returns are the only signal carrier, while a trained V makes TD lower-variance (S&B λ bias-variance; TD-Gammon λ=0.7). H2 Watkins' Q(λ) says effective λ should be LOW while exploration is high — MC returns belong to the BEHAVIOR policy, and Watkins cuts traces at non-greedy actions (Watkins 1989; S&B §12.10). RESOLUTION: the SCHEDULE follows H1 (down, same direction as τ; a noisy-but-real MC outcome beats an information-free bootstrap, and symmetric self-play noise still grades material/mating skill); H2 is carried REACTIVELY by :Variance-adaptive-λ: (committed, `QLEARN_ADAPTIVE_LAMBDA=1`): `λ_eff = clip(λ_base(p)·(1 − k·σ̂_TD), 0.1, λ_base(p))` — exploratory/off-policy-noisy data spikes σ_TD and trims λ, so a future plateau-triggered τ bump (:Uncertainty-exploration:) auto-cuts λ during the burst with no second schedule.
- :Piece-worth-observability: — for `arch="linear"` the learned piece values are read off the weights each logged sample: `v_piece = mean(w[white 64 squares]) − mean(w[black 64 squares])`, normalized pawn=1, logged as `piece_vals` and plotted live. This is the empirical test of "pieces build their own worth from checkmate-only reward" (Beal & Smith 1997: TD self-play recovers ~1/3/3/5/9).
- :Frozen-generator: — with `QLEARN_FREEZE_EPOCH=1` (default) the games AND their bootstrap values come from a FROZEN copy of the net, synced from the live net only at epoch boundaries: each epoch is a true policy-iteration step (generate from π₍ₖ₋₁₎ → fit V with ~TRAIN_STEPS minibatches → π₍ₖ₎), and epoch k's data is cleanly attributable to one known policy at one known τ. The LIVE net still takes every gradient step — freezing changes only the data-generation (and bootstrap) policy, so there is no signal collapse. This also delivers the :Target-network: future item at epoch granularity. Under freezing, τ is the ONLY exploration in the system (a frozen argmax policy from the fixed start position would replay ONE deterministic game; temperature is what turns a policy into a distribution over games).
- :Batch-of-games: — `QLEARN_BATCH_GAMES` (console "batch (games/cycle)", REQUIRED ≤ games/epoch, tuned by Optuna): games per generate→train cycle; `epoch_games / batch_games` = number of batches per epoch. Each cycle plays batch_games fresh games then takes `TRAIN_STEPS·batch/epoch_games` SGD minibatches of `QLEARN_BATCH` positions each. USER-FACING knobs are exactly two, in the user's vocabulary: **sample size** (games/epoch — the fresh draw per epoch) and **batch size** (games per gradient cycle). The positions-per-gradient-step minibatch (`QLEARN_BATCH`, 256) is an INTERNAL optimizer detail — env-overridable but deliberately NOT a console field or Optuna dimension. Decoupled from the plot cadence (`LOG_EVERY`); a plotted sample is always emitted at epoch boundaries so :Elo-patience: never reads a stale eval.
- :Reward-trace: — each logged sample records `avg_reward` (mean terminal z over the chunk's self-play games, white-absolute) and `decisive` (fraction of games ending in mate = |z|). The dashboard plots `avg_reward` as the moving-average reward curve; `decisive` is the reward-signal DENSITY (an all-draw stretch teaches nothing).
- :Convergence-watch: is the honest success criterion. Function approximation VOIDS the tabular Q-learning convergence theorem (S&B §6.5 assumes revisited states; chess never revisits), so convergence here is EMPIRICAL, not guaranteed: training loss flattens AND :Proxy-strength: rises and holds. A flat/declining :Proxy-strength: is a real (negative) result, surfaced, not hidden.

***implementation reqs***

- The engine imports Merge 0's `ChessEnv` and Merge 1's `encode` UNCHANGED and adds `ValueNet`, the afterstate policy, the λ-return targeter, the `:Replay-buffer:`, and the training loop in its own module (`qlearn.py`). It MUST NOT modify env reward semantics or the white-absolute frame.
- Hyperparameters (α, γ, λ, λ_start/λ_warmup, τ_start/τ_floor/WARMUP, epoch games/max epochs/patience, batch, buffer, arch, log cadence) are read from `QLEARN_*` env vars so `tune_qlearn.py` and the console (`server.py`) drive them via subprocess without code edits. `tune_qlearn.py` sweeps {`QLEARN_GAMMA`, `QLEARN_ALPHA`, `QLEARN_LAMBDA`, `QLEARN_WARMUP`}; the schedule knobs `QLEARN_LAMBDA_START` (0.95) and `QLEARN_LAMBDA_WARMUP` (=WARMUP) default to lock-step with τ.
- :Checkpoint-resume: — `models/qlearn.pt` is written at EVERY epoch boundary (and at the end): weights + optimizer state + CUMULATIVE game count. With `QLEARN_RESUME=1` (console "resume last model", default off) a run loads it and CONTINUES: τ/λ schedules advance on `(cum + played)/(cum + total)` so a matured net keeps its late-schedule temperature instead of being re-annealed to exploratory; the replay buffer and patience state start fresh (buffer targets are frozen-at-generation and regenerate from the current policy). Arch mismatch → fresh net with a warning. Optuna trials ALWAYS run fresh (`QLEARN_RESUME=0` forced) AND checkpoint to a SEPARATE path (`QLEARN_CKPT=models/qlearn_optuna.pt`) so a study never clobbers the console run's resumable `models/qlearn.pt` — trial hermeticity both directions. **KEEP-BEST + RATCHET**: RL learning curves are non-monotone (policy→data feedback; observed: E1/D3 peak-then-collapse), so whenever the :Elo-patience: strength improves, the run ALSO saves `*_best.pt`; resume prefers it by default (`QLEARN_RESUME_BEST=0` for latest) — chained runs then start from the best policy ANY leg reached, so one leg's late collapse cannot poison the next. Checkpoints are same-architecture snapshots selected by a held-out strength signal, never training loss.
- :Study-resume: — Optuna study names are FINGERPRINTED (`sha1(search space | regime | protocol)[:8]`): rerunning `tune_qlearn.py` with an unchanged set RESUMES that study, so TPE accumulates evidence across runs; any change to the space/regime/protocol starts a NEW study alongside (the DB is never deleted). The console/report serve the MOST RECENTLY ACTIVE study. Bump the `REGIME` string in `tune_qlearn.py` whenever training mechanics change, or stale trials will poison the resumed posterior.
- :Elo-objective: (v2, pooled) — the Optuna objective is the RUN-POOLED anchored Elo: every SF game the trial played (live per-sample games + the final measure) pooled into one score → ~5× the resolution of a 20-game final at zero extra compute (v1's final-only objective was FLAT at low budgets: whole studies of shutouts, TPE learned nothing). A small ordinal tie-break (+10 Elo · vs_random_score, bounded ≤10 Elo ≪ one real SF point ≈ 30+) gives TPE a sub-floor gradient. Emitted on the `KILL-CHECK elo` line and MAXIMIZED; the run emits it on a `KILL-CHECK ... elo <x>` stdout line. Training loss is a diagnostic ONLY, never the objective (a value can drive loss→0 by fitting its own random-play distribution and still be weak). The cheap per-iteration :Proxy-strength: is the Optuna PRUNING signal (median-prune trials whose proxy stalls), so an expensive Elo objective stays tractable.
- Metrics are written PER BATCH to `data/qlearn_metrics.jsonl` — cheap fields (loss, τ, λ_eff, TD-σ, buffer, avg_reward, decisive, piece_vals) on every row; the EXPENSIVE greedy/SF eval fields fill only on the sample cadence (every `QLEARN_LOG_EVERY` games, and always at epoch boundaries) and are None otherwise. The dashboard renders each series as faint raw per-batch points plus a bold MOVING AVERAGE (window 10), so batch-scale noise and epoch-scale drift read together. Fields — loss, τ, λ_eff, TD-error σ, buffer size, GREEDY-policy diagnostics (win-rates vs random/heuristic, material margin, turns), the NOMINAL SF score (`sf_pts`/`sf_n`) with its derived :Calibrated-elo:, `piece_vals` (:Piece-worth-observability:), and `avg_reward`/`decisive` (:Reward-trace:) — the live TRAINING curve; the FastAPI server (`server.py`) READS it, so training runs detached (launcher+interpreter TREE; stop must tree-kill) and survives dashboard refresh and server restarts (pid-file re-attach). The final anchored Elo — WITH its confidence interval (the score is a mean over games with a real standard error, so report the sdev, not just the point) — appends to `data/rl_trend.jsonl` (the ladder).
- The :ETA: display MUST carry the standing caveat: it is a naive extrapolation; reward-only self-play is expected to plateau below 1600 on this hardware, so a diverging ETA / flattening curve is the real result, not a failure of the readout.

***functional specs***

- Given a completed self-play game (win, loss, OR draw), When its positions are added to the :Replay-buffer:, Then each position s_t carries its :TD-lambda-target: `G^λ_t` — NOT the single game outcome smeared across all moves (the Merge 1 mistake).
- Given λ = 0, Then :TD-lambda-target: reduces to the one-step Q-learning update `r + γ·V(s′)`; given λ = 1, it is the Monte-Carlo return.
- Given a training iteration, When minibatches are drawn from the :Replay-buffer:, Then sampling is uniform (no weighting) and the SGD step size is α.
- Given the :Temperature-schedule:, Then τ anneals each iteration but never reaches 0 (a floor is always kept), and move selection is softmax over afterstate values (σ-signed); at τ→τ_floor it is near-greedy.
- Given the :TD-lambda-target:, Then the bootstrap uses the GREEDY/max afterstate value at s′ (off-policy), regardless of the softmax choice actually played — softmax is exploration, not the target.
- Given each iteration, Then :Proxy-strength: is measured and logged; given the periodic interval, :Calibrated-elo: is measured and logged; the dashboard plots both live and computes the caveated :ETA:.
- Given function approximation, Then :Convergence-watch: is the acceptance test — loss flattening with rising, held :Proxy-strength: — and a plateau below 1600 is reported honestly, never masked by the :ETA:.

***future direction (documented, NOT built — deliberate simplicity for now)***

Each is sound but deferred; none is built. The current rung keeps the binary win/loss/draw terminal, the
off-policy greedy target, fixed λ, and tunes ONLY the warmup ratio.

*Reward enrichment (fight sparse-terminal starvation):*

- :Potential-shaped-reward: — dense per-step reward `F = γ·Φ(s′) − Φ(s)` with Φ = material (Ng, Harada & Russell 1999). The ONLY dense-reward form that provably preserves the optimal policy; the per-step F telescopes over a game to ≈ final material, so it also delivers a graded end-of-game signal for the ~89% of draws — WITHOUT touching the binary terminal. Anneal its weight to 0 so the final objective is pure outcome. This is the sound version of "use the score / winning-well in the reward"; a raw EMA-of-score TERMINAL reward is NOT potential-based and would reward losing-while-materially-ahead.
  - Material best practice for Φ: use the DIFFERENCE (white − black), White-absolute, not nominal totals — value is about balance/antisymmetry (both sides holding queens rewards no one). Standard values P=1, N=3, B=3, R=5, Q=9; **King = 0** (always on board until the terminal, so it carries no material info; king safety is positional, handled elsewhere). Normalize Φ to [-1,1] (e.g. tanh(diff/8)) to stay commensurate with the tanh value. "Win faster / fewer moves" needs NO separate lever — the γ<1 discount already makes a mate-in-5 worth more than a mate-in-20 (γ⁵ > γ²⁰).
- :Variance-adaptive-λ: — modulate the TD↔MC dial by the return ESTIMATOR's variance (not board-eval volatility): bootstrap more where the return is high-variance. **PROMOTED TO COMMITTED** — implemented per-chunk on top of :Lambda-anneal: (see committed section). The Sharpe/sdev intuition's other sound home is advantage normalization, which belongs to the actor-critic rung, not here.
- :Elo-terminal-signal: — replace the binary ±1 with a graded strength signal. Caveat: Elo is a many-game PLAYER property, undefined per-game/position; the sound realization is an opponent-relative rating-update reward vs a rated pool (in symmetric self-play its expectation is ~0, so it needs an external rated opponent to carry information). NOTE: per-game Elo collapses to the outcome, but BATCH Elo (over N games vs the anchor) IS well-defined — and that is already the outer :Elo-objective:, not a per-step reward.

*Stability / algorithm variants:*

- :Expected-SARSA-onpolicy: — bootstrap the target on the SOFTMAX-EXPECTED afterstate value (matching the behavior policy) instead of the greedy max. This makes the method ON-policy → removes the off-policy leg of the deadly triad (FA + bootstrapping + off-policy) → more stable, at the cost of learning the *exploratory* policy's value (a hair weaker than greedy-optimal). It is a ONE-LINE change in `build_targets` and the documented on-policy alternative to the committed off-policy Q-learning. (Escaping the triad does NOT require actor-critic.)
- :Target-network: — bootstrap off a FROZEN copy of the value, synced every K iterations, so the target doesn't chase the parameters being updated. The classic DQN-era triad mitigation. Current code bootstraps on a within-iteration snapshot (mild implicit lag only).
- :Uncertainty-exploration: — UCB-style `mean + c·sdev`, or a temperature bump on high-uncertainty positions, to escape local dips ("patience"). Uncertainty-driven exploration; deferred to avoid front-loading complexity.

*Lineage — later rungs, NOT this one (see spec/README ladder):*

- :MCTS-improvement-operator: — a multi-ply search (PUCT) that produces visit counts, a STRONGER policy than this rung's 1-ply softmax. Adding it + a policy head + expert iteration (value←outcome, policy←MCTS visits) IS the AlphaZero rung (Merge 3). The current softmax-temperature self-play is the RAW 1-ply policy, not a search operator.
- :Actor-critic: — **PROMOTED TO MERGE 3** (spec/actor-critic.spec.md): online on-policy actor-critic WITH eligibility traces (S&B 13.5–13.6 transplant), adopted after Merge 2's measured ceiling (~650 pooled, data/experiments.md). The on-policy formulation removes the deadly triad's off-policy leg; Merge 2's replay/frozen-generator machinery does NOT carry over there.

- **On-policy vs off-policy here?** Does :Expected-SARSA-onpolicy: (out of the triad) beat the committed off-policy greedy target on Elo and stability on this hardware?
